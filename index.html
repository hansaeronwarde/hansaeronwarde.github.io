ESC Partners · Utilities

Delco ↔ Beacon Integration Middleware

Custom middleware replacing Oracle Integration Cloud for utility billing, meter data, and customer record workflows — at a fraction of the cost.

The Problem

Delco and Beacon had no integration layer. The options were manual request handling by operations teams, or licensing Oracle Integration Cloud — expensive and over-engineered for the use case. Meanwhile, requests were synchronous, failed jobs disappeared without visibility, and batch imports followed a completely separate path from real-time requests.

The Approach

Built a purpose-built event-driven middleware from scratch. Incoming requests were acknowledged immediately and queued for async execution. Workers processed jobs at controlled concurrency (5 parallel) to protect downstream APIs. Used MongoDB as both the primary store and caching layer for request state, giving fast reads on job status without hitting external systems. Every request followed a state machine — pending → processing → completed / failed — with full lifecycle tracking, retry handling for transient failures, and polling for long-running external jobs. Built a file processing pipeline for batch CSV imports: download, parse, validate, transform, upload, and cleanup.

Key Decisions

Custom middleware over Oracle IC — lower cost, full control, purpose-built for the actual workflow. FIFO queue with controlled parallelism to prevent cascading failures. MongoDB for dual-purpose storage and caching. Polling over blocking to keep workers productive during external waits. Unified pipeline for both real-time and batch workflows.

Circles.Life · Telecom

End-to-End SIM Activation & Delivery Engine

Event-driven backend handling 100k+ concurrent users across the full lifecycle — from SIM purchase through activation to last-mile delivery.

The Problem

The activation system was buried inside a tightly coupled monolith. Deployments were risky, test coverage was near-zero, and the system couldn't handle traffic spikes without degrading the entire platform. Delivery was disconnected — there was no integration between activation and logistics, leaving the customer experience fragmented across purchase, activation, and fulfillment.

The Approach

Decomposed the monolith into independently deployable Go and Node.js services behind an event-driven architecture. Isolated the activation flow so it could scale, fail, and deploy independently. Extended the system end-to-end by integrating with third-party logistics providers for last-mile delivery — including rider fulfillment services operating in markets like Pakistan. Built comprehensive test coverage across critical paths.

Manulife · Insurance

Intelligent Document Capture System

OCR-powered document intake platform for insurance claims, starting with dental — built on Azure Cognitive Services with a custom-trained extraction model.

The Problem

Insurance claims were manually encoded by operations teams — every document was read, interpreted, and keyed in by hand. The process was slow, error-prone, expensive, and didn't scale. There was no audit trail and no consistency in how claims were routed.

The Approach

ESC Partners · Utilities

Utility Campaign & Notification Manager

Multi-channel notification platform unifying SMS, IVR, and email delivery for utility campaigns — replacing fragmented vendor workflows with a single orchestration layer serving 50,000+ customers.

The Problem

Utilities managed notifications through separate vendors for SMS, IVR, and email. Campaigns required coordinating across disconnected systems with no unified tracking, shared templates, or centralized audit trail, and scheduling, delivery status, and campaign history were scattered. As the client base grew across Alex Renew, MVU, and Delco — with Delco alone serving 50,000+ water customers — this fragmented setup could not scale.

The Approach

Built a unified campaign manager allowing utility operators to configure and launch multi-channel notifications from a single interface, selecting SMS, IVR, email, or combinations, defining audiences, and scheduling delivery. Integrated Twilio for SMS/IVR and AWS SES for email, abstracting vendor differences behind a consistent delivery layer. Added a Mustache-based dynamic templating system for personalized content, scheduling for future campaigns, and full audit logging for sent, failed, and pending notifications across all channels.

Key Decisions

Implemented a single orchestration layer instead of managing separate vendor tools for each channel. Used Mustache for lightweight, logic-less templating capable of high-volume personalization. Channel selection was left to operators, as utilities know their customers' preferred contact methods.
