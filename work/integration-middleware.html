01Situation

Two systems, no integration layer.

Delco and Beacon had no integration layer. The options were manual handling by operations teams, or licensing Oracle Integration Cloud.

02Constraint

Failed jobs disappeared without a trace.

Requests were synchronous, failed jobs disappeared without a trace, and batch imports took a separate path from real-time requests. The downstream APIs had to be protected from load.

04Decision

Own the integration, and cap concurrency to protect downstream APIs.

THE BOUNDARY A request keeps its identity. Acknowledge before doing the expensive work. The request record outlives an individual worker attempt.

NOT CHOSEN Licensing Oracle Integration Cloud. Custom middleware gave full control and a fit to the actual workflow.

  • A FIFO queue with capped parallelism, so one slow system can't cascade.
  • MongoDB for storage and cache in one.
  • Polling instead of blocking, so workers stay busy during external waits.
  • One pipeline for real-time and batch work.
05Model

Bound the concurrency.

Set downstream capacity below the worker count and run the batch. Requests that find no free slot wait and retry, up to three attempts, and every one keeps its record.
