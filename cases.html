The problem

Delco and Beacon had no integration layer. The options were manual handling by operations teams, or licensing Oracle Integration Cloud. Requests were synchronous, failed jobs disappeared without a trace, and batch imports took a separate path from real-time requests.

The approach

I wrote event-driven middleware from scratch. It acknowledges each request at once and queues it. Five workers process the queue, which caps the load on downstream APIs. MongoDB holds request state as both store and cache, so status reads don't hit the external systems.

Every request moves through one state machine: pending, processing, then completed or failed. Transient failures retry; long-running external jobs are polled. Batch CSV imports run through the same pipeline: download, parse, validate, transform, upload, clean up.

Key decisions

Custom middleware over Oracle Integration Cloud, for full control and a fit to the actual workflow. A FIFO queue with capped parallelism, so one slow system can't cascade. MongoDB for storage and cache in one. Polling instead of blocking, so workers stay busy during external waits. One pipeline for real-time and batch work.

The problem

Operations teams keyed in every claim by hand: read the paper, interpret it, type it. It was slow, error-prone and expensive, and it didn't scale. Routing was inconsistent, and nothing recorded who changed what.

The approach

Encoders went from typing claims to checking them. I trained a custom OCR model in Azure Cognitive Services to pull structured data from dental claims first. The problem

Utilities sent notifications through separate vendors for SMS, IVR and email. Each campaign meant coordinating disconnected systems, with no shared templates, tracking or audit trail. Schedules, delivery status and history lived in different places. As the client base grew to Alex Renew, MVU and Delco, which alone serves 50,000+ water customers, that setup couldn't scale.

The approach

I built one campaign manager where utility operators pick SMS, IVR, email or any mix, define the audience and schedule the send. Twilio carries SMS and IVR; AWS SES carries email. One delivery layer hides the differences between vendors. Mustache templates personalize each message, and an audit log records every notification as sent, failed or pending, on every channel.

Key decisions

One orchestration layer instead of a vendor tool per channel. Mustache for templates, because logic-less templates stay fast and safe at high volume. Channel choice stays with operators, because utilities know how their customers want to be reached.
