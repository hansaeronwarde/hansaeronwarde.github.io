N4 / 04 / ENGINEERING NOTEFROM ALL FOUR SYSTEMS

Operating a legacy rebuild from interface to production.

Each of the four systems replaced something people already relied on. A rebuild like that is finished when it runs, not when it ships, and every layer has a question to answer first.

Layers
All six, interface to operation
Cases
01–04 / Selected systems
Scope
General practice, not client evidence
01Claim

Own every layer the change touches.

A new interface on an old data model, or a new service nobody is watching, moves the risk instead of removing it. The person leading the rebuild should be able to answer for each layer, from what the user sees to what wakes someone at night.

03Pattern

Move traffic by share, keep the old path live.

Route a stable share of accounts to the new path. The same account always lands on the same side, and the old path keeps serving until the share reaches 100. 

function bucket(id) {
  let hash = 0;
  for (const ch of String(id)) hash = (hash * 31 + ch.charCodeAt(0)) >>> 0;
  return hash % 100;
}

function route(request, { share }) {
  return bucket(request.accountId) < share
    ? newPath(request)
    : oldPath(request);
}
04Contract

What each layer can rely on during the move.

People
The same task works on either path; nobody has to know which one served them
Services
Both paths accept the same request
Data
One writer per record at any moment: migrate, then switch writes
Operations
Dashboards and alerts exist before the first request moves
05Tradeoffs

Two paths cost more than one, for a while.

  • Running both paths doubles what you operate. Set the date the old one goes.
  • Writing to both stores drifts. Prefer one writer and a backfill.
  • A rollback nobody has rehearsed is a hope. Rehearse it at a small share.
06Operating

Compare the paths at every step.

Test
End-to-end tests on the user's task, run against both paths
Deploy
Raise the share in steps, through the same pipeline as any change
Observe
Errors and latency per path at each share, before raising it again
07Scope

General practice, not a client trace.

The questions and pattern are general practice. They do not describe how any one client migration was sequenced. Each “Seen in” link points to the case that shows that layer best, with its reported outcome.
