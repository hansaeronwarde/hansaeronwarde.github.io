03Pattern

Validate the correction. Refuse the unreviewed.

The reviewer's value passes the same rules as any input, and a field with no rule is refused. The record keeps before and after, and routing refuses a claim until every field has been approved at its current value, so an extracted field with no rule holds the claim. 

const rules = {
  amount: (value) =>
    typeof value === "string" && /^\d+\.\d{2}$/.test(value)
      ? null
      : "not_a_number",
};

function review(claim, field, after, reviewer) {
  if (!Object.hasOwn(rules, field))
    return { ok: false, problem: "unknown_field" };
  const problem = rules[field](after);
  if (problem) return { ok: false, problem };
  const before = claim.fields[field];
  claim.fields[field] = after;
  claim.history.push({
    event: "reviewed", field, before, after, reviewer,
    at: new Date().toISOString(),
  });
  return { ok: true };
}

function route(claim) {
  const fields = new Set([
    ...Object.keys(rules),
    ...Object.keys(claim.fields),
  ]);
  const unreviewed = [...fields].filter((field) => {
    const last = claim.history.findLast(
      (e) => e.event === "reviewed" && e.field === field,
    );
    return !last || last.after !== claim.fields[field];
  });
  if (unreviewed.length)
    throw new Error(`Review first: ${unreviewed.join(", ")}`);
  claim.history.push({ event: "routed" });
}
04Contract

What each layer can rely on.

Reviewer
The source region beside the extracted value, and an error that says what is wrong while focus stays on the field
Service
Nothing routes until a person has approved every field at its current value
State
Before, after, who and when, for every field a person changed
05Tradeoffs

Review is a queue too.

  • People stay in the workflow. If the review queue grows, the savings shrink.
  • Reviewers who see only the value learn to approve it. Show the evidence it came from.
  • A correction teaches nothing unless it is stored with the value it replaced.
